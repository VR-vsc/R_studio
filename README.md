## Зачем это нужно

В квартире современного ЖК — датчики протечки, термостат, шлагбаум, счётчики, вентиляция. Каждое устройство работает само по себе, и связать их в работающие вместе правила трудно:

- у каждого устройства свой формат сигналов;
- сценарий «протечка → перекрыть воду» нечем проверить без настоящей протечки;
- правила конфликтуют между собой и зацикливаются.

R Studio решает это в одном веб-приложении.

## Быстрый старт

Нужен **Python 3.10 или новее**. Node.js для запуска **не нужен**: интерфейс уже собран и лежит в `frontend/dist`.

```bash
git clone <адрес-репозитория> r-studio
cd r-studio/backend
pip install -r requirements.txt
python -m uvicorn app.main:app --port 8000
```

Откройте в браузере **http://127.0.0.1:8000**.

Быстрее всего посмотреть так: «Обзор» → блок «Показать за минуту» → «Протечка в ванной».

## Подробная установка

### 1. Проверьте Python

```bash
python --version
```

Нужна версия 3.10 или выше. Если Python нет, скачайте его с [python.org](https://www.python.org/downloads/). В установщике Windows отметьте галочку **«Add Python to PATH»**.

### 2. Создайте виртуальное окружение (рекомендуется)

Окружение изолирует библиотеки проекта от остальной системы.

**Windows (PowerShell или cmd):**
```bat
cd r-studio\backend
python -m venv .venv
.venv\Scripts\activate
```

**macOS / Linux:**
```bash
cd r-studio/backend
python3 -m venv .venv
source .venv/bin/activate
```

Когда окружение активно, в начале строки терминала появляется `(.venv)`.

### 3. Установите зависимости

```bash
pip install -r requirements.txt
```

Ставятся FastAPI, Uvicorn, Pydantic, websockets, а для тестов — pytest и httpx.

### 4. Запустите сервер

```bash
python -m uvicorn app.main:app --port 8000
```

Сервер готов, когда в терминале появится строка:
```
Uvicorn running on http://127.0.0.1:8000
```

| Адрес | Что там |
|---|---|
| http://127.0.0.1:8000 | интерфейс R Studio |
| http://127.0.0.1:8000/docs | интерактивная документация API (Swagger) |

**Остановить сервер:** `Ctrl+C` в окне терминала. Пока окно открыто, сайт работает.

### 5. Показать с другого устройства в той же сети (необязательно)

```bash
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Узнайте свой IP командой `ipconfig` (Windows) или `ip a` (Linux) и откройте на другом устройстве `http://<ваш-IP>:8000`. Windows может спросить разрешение брандмауэра — нажмите «Разрешить».

### Где хранятся данные

Все данные — обычные JSON-файлы в `backend/data/`: библиотека устройств, квартира, сценарии, настройки Ujin. При первом запуске папка заполняется готовыми устройствами и сценариями.

- **Начать с чистого листа:** остановите сервер и удалите папку `backend/data`.
- **Хранить данные в другом месте:** задайте переменную окружения `RSTUDIO_DATA=путь/к/папке`.

## Как пользоваться

1. **Устройства.** Выберите устройство слева или создайте новое. Редактируйте сигналы и правила в форме. Справа «Проверка» → «Проверить» покажет графики работы. Сохранение — кнопкой или `Ctrl+S`.
2. **Сценарии.** Соберите правило: Когда → И если → То. Справа видно, как сценарий читается по-русски, найденные ошибки и экспорт для Ujin. Кнопка «Проверить сценарий» прогонит его на копии квартиры и выдаст вердикт.
3. **Эмуляторы.** Нажмите «Запустить» и меняйте «мир вокруг» в зелёных блоках карточек. Справа вкладки «Сценарии» (что сработало и почему), «Уведомления», «События», «Журнал». Кнопка «Демо» запускает готовые истории с подписями.
4. **Ujin OS.** Подключение к стенду — следующий раздел.

---

## Подключение к стенду Ujin

1. Откройте вкладку **Ujin OS**.
2. Нажмите **«Загрузить доступы.json»** и выберите файл доступов из пакета команды. R Studio возьмёт адрес API, токен жителя и квартиру, а также привяжет устройства.
3. Выберите режим **«Пробный»** → «Отправить всё сейчас». В журнале справа будет видно, какие запросы ушли бы на стенд; на самом деле ничего не отправляется.
4. Нажмите **«Проверить связь»**: должно быть «Стенд доступен» и «Токен резидента принят».
5. Включите режим **«На стенд»**: значения привязанных устройств начнут уходить в Ujin каждые 2 секунды.

> ⚠️ **Не публикуйте `доступы.json` и токены.** Файл исключён в `.gitignore`. Токены хранятся только в `backend/data/ujin.json` и в интерфейсе показываются замаскированными.

Особенности стенда тест-ОАЭ и результаты проверки 31.10.2026 описаны в [docs/UJIN.md](docs/UJIN.md).

## Тесты

```bash
cd backend
python -m pytest -q
```

Ожидаемый результат: **54 passed**. Тесты работают без сети, для интеграции с Ujin используется локальная заглушка стенда.

## Разработка интерфейса

Нужно, только если вы меняете код в `frontend/src`. Требуется [Node.js](https://nodejs.org/) 18 или новее.

```bash
cd frontend
npm install          # один раз: поставит React, TypeScript, Vite, Tailwind
npm run dev          # режим разработки: http://localhost:5173
```

В режиме разработки запросы `/api` автоматически идут на сервер на порту 8000, поэтому backend должен быть запущен.

Чтобы изменения попали в основную версию на порту 8000, соберите интерфейс:
```bash
npm run build        # обновит frontend/dist
```

> Если VS Code подчёркивает весь React-код красным, значит, не выполнен `npm install`: редактор не видит библиотеки. Сайт на порту 8000 при этом работает, потому что использует уже собранную версию.

```

├── backend/
│   ├── app/
│   │   ├── main.py              точка входа FastAPI, запуск фоновых задач
│   │   ├── api_devices.py       API конструктора устройств
│   │   ├── api_emulation.py     API эмуляторов + WebSocket
│   │   ├── api_scenarios.py     API сценариев
│   │   ├── api_ujin.py          API интеграции с Ujin
│   │   ├── api_demo.py          главная и демо-истории
│   │   ├── rdl/                 язык описания устройств
│   │   │   ├── models.py        структура языка (Pydantic)
│   │   │   ├── validate.py      проверка смысла, ошибки по-русски
│   │   │   ├── expr.py          безопасные формулы (без eval)
│   │   │   ├── runtime.py       описание → работающее устройство
│   │   │   └── templates/       9 готовых устройств
│   │   ├── emulation.py         квартира: такты, команды, события
│   │   ├── scenarios.py         язык сценариев, проверка, экспорт
│   │   ├── scenarios_seed/      7 готовых сценариев
│   │   ├── engine.py            движок исполнения сценариев
│   │   ├── ujin.py              мост в Ujin OS
│   │   ├── demo.py              демо-истории
│   │   └── storage.py           хранение JSON-файлов
│   ├── emulators/               эмуляторы из стартового пакета Ujin
│   ├── tests/                   автотесты (pytest)
│   ├── data/                    данные (создаётся при запуске, не в git)
│   └── requirements.txt
├── frontend/
│   ├── src/
│   │   ├── App.tsx              меню и переключение вкладок
│   │   ├── pages/               страницы: Home, Constructor, Scenarios, Emulators, Ujin
│   │   ├── components/          части страниц
│   │   ├── lib/                 запросы к API, типы, утилиты
│   │   └── styles.css           цвета и общие стили (Tailwind)
```

## Архитектура

```
Браузер (React + TypeScript)
   │   HTTP  /api/...        — запросы и ответы в JSON
   │   WebSocket /api/emu/ws — живые обновления квартиры
   ▼
Сервер (Python + FastAPI)
   ├── rdl         описание устройства → RDLDevice (наследник Device из стартового пакета)
   ├── emulation   квартира: каждую секунду такт, рассылает события подписчикам
   ├── engine      подписан на квартиру, исполняет сценарии, пишет трассу
   ├── ujin        подписан на квартиру, отправляет значения на стенд
   └── storage     JSON-файлы в backend/data
   │
   ▼  HTTPS + JSON
Стенд Ujin OS (api-uae-test.ujin.tech)
```

| Слой | Технологии | Почему |
|---|---|---|
| Сервер | Python, FastAPI, Pydantic, asyncio, Uvicorn | стартовый пакет Ujin на Python; проверка данных и документация API из коробки; WebSocket |
| Интерфейс | React, TypeScript, Vite, Tailwind CSS | компоненты, проверка типов, быстрая сборка, единая палитра |
| Данные | JSON-файлы | запуск одной командой, без базы данных |
| Качество | pytest, Playwright | 54 автотеста и проверка интерфейса в браузере |

## Частые проблемы

| Проблема | Решение |
|---|---|
| `python` не найден | установите Python и отметьте «Add Python to PATH»; на macOS/Linux используйте `python3` |
| `No module named fastapi` | не установлены зависимости или не активно окружение: `pip install -r requirements.txt` |
| `address already in use` / порт занят | сервер уже запущен в другом окне — закройте его или используйте `--port 8001` |
| Страница не открывается | проверьте, что окно с сервером открыто и в нём нет ошибок |
| После обновления кода ничего не изменилось | перезапустите сервер (`Ctrl+C` и запуск заново); для изменений во `frontend/src` выполните `npm run build` |
| В «Эмуляторах» «нет связи с сервером» | сервер остановлен или перезапускается — страница переподключится сама |
| Ujin: «нет связи со стендом» | нет интернета или стенд недоступен; остальные разделы работают без сети |
